# Brief 5.1: Header thí nghiệm dùng chung (có git commit)

## 0. Bắt buộc đọc trước
- `AGENTS.md` (toàn bộ; §6 Giao thức bằng chứng ưu tiên cao nhất) và `.agents/rules/evidence_protocol.md`.
- `tasks/roadmap.md` §0 (ràng buộc hạ tầng Kaggle/Colab) và Phase 5.
- Skill gợi ý: `.agents/skills/test-driven-development/SKILL.md`.

## 1. Bối cảnh
- Mỗi script thí nghiệm hiện tự định nghĩa lại `sha256_file` và tự in header. Có 7 file như vậy (`logs/brief51_context.log:2-8`).
- Header hiện tại có ba vấn đề, thấy ở `experiments/phase3_i6_no_compression.py:86-91`:
  - `device=cpu` được **gõ cứng**, trái AGENTS.md §6.D. Khi chạy trên GPU Kaggle, header sẽ ghi sai.
  - Nonce in ở một dòng riêng, header ở dòng sau. AGENTS.md §6.C yêu cầu header nằm ở **dòng đầu**.
  - Không ghi git commit. Khi notebook Kaggle clone repo, không có cách chứng minh log được sinh từ phiên bản code nào.

## 2. Mục tiêu (một hành vi duy nhất)
Tạo module `experiments/_header.py` để các script thí nghiệm **từ nay về sau** gọi một hàm duy nhất. Hàm đó in header trên **một dòng**, mọi giá trị đều được **tính lúc chạy**.

## 3. Phạm vi
- Được tạo:
  - `experiments/_header.py`
  - `tests/test_experiment_header.py`
  - `experiments/phase5_header_demo.py` (script mẫu, chỉ gọi header rồi thoát)
- KHÔNG được sửa:
  - **Mọi script `experiments/phase*.py` hiện có.** Đó là bằng chứng lịch sử; sửa chúng sẽ làm sha256 trong các báo cáo cũ không còn khớp.
  - `src/`, các test hiện có, `experiments/run_exp.ps1`.

## 4. Yêu cầu chức năng
Hàm `print_header(nonce: str, seed: int, script_path: str) -> dict` in đúng **một dòng** bắt đầu bằng `[HEADER]`, theo dạng `key=value`, và trả về dict cùng nội dung. Các trường bắt buộc:

| Trường | Cách lấy (phải tính, không gõ tay) |
|---|---|
| `nonce` | tham số |
| `timestamp` | `datetime.now().isoformat()` |
| `python`, `torch`, `transformers` | `sys.version`, `torch.__version__`, `transformers.__version__` |
| `device` | `cuda` kèm tên GPU nếu `torch.cuda.is_available()`, ngược lại `cpu` |
| `seed` | tham số; hàm cũng **đặt** seed cho `random`, `numpy` (nếu có), `torch` |
| `script_sha256` | sha256 của `script_path` |
| `git_commit` | `git rev-parse HEAD`; nếu thất bại thì ghi `KHONG_XAC_DINH` và in lý do lỗi thật ở dòng `[HEADER-WARN]` ngay sau |
| `git_dirty` | `true`/`false` từ `git status --porcelain` (có file đã sửa chưa commit hay không) |

- Không được `print("PASS")` hay in giá trị cố định.
- Không dùng `except: pass`. Lỗi git phải hiện ra ở `[HEADER-WARN]`.

## 5. Các bước
1. Viết `tests/test_experiment_header.py` **trước**. Chạy nó khi chưa có module, lưu log FAIL.
   → kiểm chứng: `.venv_v5/Scripts/python.exe -m pytest tests/test_experiment_header.py -q 2>&1 | tee logs/phase5_1_test_fail.log`
2. Viết `experiments/_header.py` cho test PASS.
   → kiểm chứng: lệnh như trên, tee ra `logs/phase5_1_test_pass.log`
3. Đột biến: tạm cho `device` trả chuỗi cố định `"cpu"`, hoặc bỏ trường `git_commit`. Test phải FAIL. Lưu `logs/phase5_1_test_mutation.log`, rồi hoàn tác đột biến.
4. Viết `experiments/phase5_header_demo.py` gọi `print_header`, rồi chạy qua runner (mục 7).
5. Chạy toàn bộ test suite.
   → kiểm chứng: `.venv_v5/Scripts/python.exe -m pytest tests/ -q 2>&1 | tee logs/phase5_1_full_pytest.log`

## 6. Tiêu chí chấp nhận (phải được TÍNH, in expected/actual)
- [ ] Test kiểm tra rằng dòng đầu tiên của stdout bắt đầu bằng `[HEADER]` và chứa đủ 10 trường ở mục 4.
- [ ] Test so `script_sha256` với sha256 tự tính của file tạm (in expected/actual).
- [ ] Test so `git_commit` với `git rev-parse HEAD` chạy độc lập (in expected/actual).
- [ ] Test mô phỏng git lỗi (monkeypatch `subprocess`) và kiểm tra có `git_commit=KHONG_XAC_DINH` cùng dòng `[HEADER-WARN]`.
- [ ] Test `device` khớp `torch.cuda.is_available()` tại thời điểm chạy.
- [ ] Unit test chạy trên CPU < 0.1s mỗi test (AGENTS.md §5), trừ test gọi git thật, vốn được phép chậm hơn và phải ghi rõ.
- [ ] Đủ 3 log hai chiều: FAIL (chưa có module) / PASS / đột biến FAIL.
- [ ] Toàn bộ test suite xanh. Trước khi làm có 43 test pass (`logs/review_arch_pytest.log`).
- [ ] Mỗi file mới ≤ 250–300 dòng.
- [ ] `git diff --stat` chỉ có 3 file mới ở mục 3.

## 7. Lệnh chạy thí nghiệm
```powershell
./experiments/run_exp.ps1 -Script experiments/phase5_header_demo.py -Nonce <NONCE> -Tag phase5_1_header_demo -Py .venv_v5/Scripts/python.exe
```
Người dùng cung cấp `<NONCE>`. **Không tự đặt.** Dòng 1 của `logs/phase5_1_header_demo.log` phải là `[HEADER] nonce=<NONCE> ...`.

## 8. Điều kiện dừng
- Cùng một hướng sửa thất bại 2 lần: DỪNG, nộp log, chờ người dùng.
- Nếu cho rằng brief sai, ví dụ thấy cần sửa script cũ: giải thích, không tự làm, chờ duyệt.
- Không chạy được, ví dụ không có git: ghi "KHÔNG CHẠY ĐƯỢC: <lý do>" kèm lỗi thật.

Viết `reports/5.1_experiment_header_report.md` theo đúng mẫu dưới. Không commit; người hướng dẫn sẽ review trước.
